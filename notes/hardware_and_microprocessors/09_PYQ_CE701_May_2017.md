### Q1(a) [5 Marks]
**Question:**  
*Show the physical address calculation process for 8086 microprocessor for various segments with neat illustration.*

#### 1. Concept & Architectural Formulation
The 8086 generates 20-bit physical addresses using 16-bit registers by shifting the segment base 4 bits left and adding the effective address:

$$\text{Physical Address} = (\text{Segment Base Register} \times 10\text{H}) + \text{Effective Address (Offset)}$$

```
+------------------+-----------------------+-----------------------------+------------------------------------+
| Segment Type     | Segment Register Base | Pointer / Offset Registers  | Hardware Physical Mapping          |
+------------------+-----------------------+-----------------------------+------------------------------------+
| **Code Segment** | CS (Code Segment)     | IP (Instruction Pointer)    | PA = (CS * 16) + IP                |
| **Data Segment** | DS (Data Segment)     | BX, SI, DI, Displacement    | PA = (DS * 16) + EA                |
| **Stack Segment**| SS (Stack Segment)    | SP (Stack Pointer), BP      | PA = (SS * 16) + (SP or BP)        |
| **Extra Segment**| ES (Extra Segment)    | DI (String Destination)     | PA = (ES * 16) + DI                |
+------------------+-----------------------+-----------------------------+------------------------------------+
```

```
Segment Register (16-bit):  | S15 | S14 | ... | S1 | S0 | 0 | 0 | 0 | 0 |  (Appended 4 zeros = x16)
Offset Register (16-bit):               | O15 | O14 | ... | O1 | O0 |  (Effective Address)
---------------------------------------------------------------------
Physical Address (20-bit):  | A19 | A18 | ... | A3 | A2 | A1 | A0 |  (1 MB physical range)
```

### Q1(c) [5 Marks]
**Question:**  
*Give the importance of DT/R, ALE, DEN, INTA and NMI control signals of 8086 microprocessor.*

#### 1. Signal Definitions
- **$\text{DT}/\overline{\text{R}}$ (Data Transmit/Receive, Pin 27):** Output control signal used with bus transceivers (Intel 8286). When high ($1$), data flows from CPU to bus (Transmit/Write). When low ($0$), data flows into CPU from bus (Receive/Read).
- **ALE (Address Latch Enable, Pin 25):** Output strobe pulse generated during clock state $T_1$ of every bus cycle to latch valid memory/IO addresses from multiplexed lines $AD_0 - AD_{15}$ into external latches (Intel 8282).
- **$\overline{\text{DEN}}$ (Data Enable, Pin 26):** Active-low output enabling external data bus transceivers during states $T_2 - T_4$, isolating the data bus during $T_1$ to prevent address/data bus contention.
- **$\overline{\text{INTA}}$ (Interrupt Acknowledge, Pin 24):** Active-low output pulse generated in response to an active `INTR` line, signaling the 8259A PIC to place its vector type byte on data bus lines $D_0 - D_7$.
- **NMI (Non-Maskable Interrupt, Pin 17):** High-priority, edge-triggered (low-to-high) input that bypasses the Interrupt Flag (`IF`). Automatically invokes Interrupt Type 2 for parity errors or power outages.

### Q2(b) [5 Marks]
**Question:**  
*Give pros and cons of 8086 microprocessor segmentation.*

#### 1. Pros of Segmentation
1. **Dynamic Code Relocation:** Programs can be placed anywhere in physical memory by changing base registers.
2. **Modular Organization:** Natural division between executable instructions, variables, and stack frames.
3. **Addressing Beyond 16 Bits:** Enables 16-bit registers to address a 1 MB physical address space.
4. **Shared Code Blocks:** Multiple programs can execute the same reentrant code segment concurrently.

#### 2. Cons of Segmentation
1. **64 KB Boundary Ceiling:** A single segment cannot exceed 64 KB; large arrays spanning $>64\text{ KB}$ require cumbersome segment switching.
2. **Translation Latency:** Requires hardware adder latency to calculate $(\text{Segment} \times 16) + \text{Offset}$ on every bus access.
3. **Memory Fragmentation:** Dynamic allocation of 64 KB segments leads to external physical memory fragmentation.

### Q2(b) OR [5 Marks]
**Question:**  
*Give the importance and the information stored in descriptor of 80286 processor.*

#### 1. 80286 Segment Descriptor Format (8 Bytes)
```
Byte 7: Reserved by Intel (Must be 0 in 80286)
Byte 6: Reserved by Intel (Must be 0 in 80286)
Byte 5: Access Rights Byte (P, DPL (2 bits), S, Type (4 bits))
Byte 4: Base Address Bits 23..16
Byte 3: Base Address Bits 15..8
Byte 2: Base Address Bits 7..0
Byte 1: Segment Limit Bits 15..8
Byte 0: Segment Limit Bits 7..0
```
- **Information Stored:**
  1. **24-Bit Physical Base Address:** Direct physical base location in 16 MB memory ($2^{24} = 16,777,216\text{ bytes}$).
  2. **16-Bit Segment Limit:** Specifies segment size ($0 \text{ to } 65,535\text{ bytes}$). Offsets $> \text{Limit}$ generate a General Protection Fault.
  3. **Access Rights Byte:**
     - **P (Present Bit):** $1 = \text{Segment loaded in RAM}$, $0 = \text{Virtual memory fault}$.
     - **DPL (Descriptor Privilege Level, 2 bits):** Privilege rings (0 Kernel to 3 User).
     - **S (System/Non-System):** $1 = \text{Code/Data segment}$, $0 = \text{Control descriptor (Gate/TSS)}$.
     - **Type (4 bits):** Read/Write/Execute permissions and direction (expand-down for stacks).

### Q2(c) [5 Marks]
**Question:**  
*With detailed 8086 memory bank organization show that it requires two machine cycles to complete one read or write operation if word data is stored beginning from odd address. Also specify the associated signals for byte and word operations.*

#### 1. Detailed Signal Table

| $\overline{\text{BHE}}$ | $A_0$ | Operation Performed | Data Bus Lines | Machine Cycles |
|:---:|:---:|:---|:---:|:---:|
| **0** | **0** | 16-bit Word at Even Address (Aligned) | $D_0 - D_{15}$ (Simultaneous) | **1** |
| **1** | **0** | 8-bit Byte at Even Address | $D_0 - D_7$ (Lower Bank) | **1** |
| **0** | **1** | 8-bit Byte at Odd Address | $D_8 - D_{15}$ (Upper Bank) | **1** |
| **Two-Cycle Transfer** | | **16-bit Word at Odd Address (Misaligned)** | | **2** |

#### 2. Two-Cycle Transfer Sequence for Misaligned Word
When accessing a 16-bit word starting at odd address $N$:
- **Cycle 1 (Odd Byte Transfer):** Address $N$ is asserted. $A_0 = 1$ and $\overline{\text{BHE}} = 0$. The lower byte of the word is transferred through Upper Bank ($D_8 - D_{15}$).
- **Cycle 2 (Even Byte Transfer):** The CPU increments address to $N + 1$ (even). $A_0 = 0$ and $\overline{\text{BHE}} = 1$. The higher byte is transferred through Lower Bank ($D_0 - D_7$).
- Therefore, accessing a word at an odd address requires **two full 4-state bus cycles (8 T-states)**.

### Q3(a) OR [10 Marks]
**Question:**  
*Write 8086 microprocessor interrupt service routine for a NMI interrupt to add byte type data stored in an array of size 100, starting at address 2000H: 5000H in memory with the corresponding data in another array of size 100, stored in memory starting at the address 3000H: 5000H. Store the result in another array in memory starting at the address 4000H: 5000H. Neglect the carry generated during addition.*

#### 1. Concept & IVT Vector for NMI
- **NMI Vector:** Type 2 interrupt located at physical memory address range $00008\text{H} - 0000\text{B}\text{H}$ ($\text{Base} = 2 \times 4 = 00008\text{H}$).
- **Far Segment Access:** Array 1 in `2000H`, Array 2 in `3000H`, Destination in `4000H`.

#### 2. Assembly ISR Implementation
```assembly
.MODEL LARGE
.CODE
PUBLIC NMI_ISR

NMI_ISR PROC FAR
    PUSHA               ; Preserve AX, CX, DX, BX, SP, BP, SI, DI
    PUSH DS
    PUSH ES

    MOV CX, 100         ; 100 byte elements
    XOR SI, SI          ; Offset index = 0

ADD_LOOP:
    ; Read byte from Array 1 (2000H:5000H + SI)
    MOV AX, 2000H
    MOV DS, AX
    MOV AL, DS:[5000H + SI]

    ; Read byte from Array 2 (3000H:5000H + SI) and add
    MOV BX, 3000H
    MOV DS, BX
    ADD AL, DS:[5000H + SI]  ; Carry neglected as per instructions

    ; Store result into Array 3 (4000H:5000H + SI)
    MOV BX, 4000H
    MOV ES, BX
    MOV ES:[5000H + SI], AL

    INC SI
    LOOP ADD_LOOP

    POP ES
    POP DS
    POPA
    IRET                ; Return from interrupt
NMI_ISR ENDP
END
```

### Q3(b) [10 Marks]
**Question:**  
*Assume a symbol table with name as TABLE consisting of 100 entries. Each entry has 80 bytes with the first 8 bytes representing the name field of an entity and the remaining 72 bytes represents information about the name entity. Write 8086 assembly program sequence to search this TABLE for a given name stored in a variable SEARCH_NAME and if SEARCH_NAME is found in TABLE then the program should copy 72 bytes of information in variable NAME_INFO. If SEARCH_NAME is not found then NAME_INFO should contain `'$'` symbol.*

#### 1. Assembly Solution
```assembly
.MODEL SMALL
.STACK 100H
.DATA
    ENTRY_COUNT EQU 100
    ENTRY_SIZE  EQU 80
    NAME_LEN    EQU 8
    INFO_LEN    EQU 72

    TABLE       DB ENTRY_COUNT * ENTRY_SIZE DUP(0) ; 8,000 bytes
    SEARCH_NAME DB 'MATH_VAR'                     ; 8 bytes
    NAME_INFO   DB INFO_LEN DUP(?)

.CODE
MAIN PROC
    MOV AX, @DATA
    MOV DS, AX
    MOV ES, AX

    LEA BX, TABLE       ; BX points to base of current entry
    MOV CX, ENTRY_COUNT

TABLE_SCAN:
    ; Compare 8-byte Name Field
    LEA SI, SEARCH_NAME
    MOV DI, BX          ; DI points to entry name
    PUSH CX
    MOV CX, NAME_LEN
    CLD
    REPE CMPSB
    POP CX
    JE ENTRY_FOUND      ; Match found!

    ADD BX, ENTRY_SIZE  ; Advance to next 80-byte record
    LOOP TABLE_SCAN

    ; NOT FOUND: Store `'$'` into NAME_INFO
    MOV BYTE PTR NAME_INFO, `'$'`
    JMP FINISH_PROGRAM

ENTRY_FOUND:
    ; Copy 72 bytes of Info Field (located at BX + 8) into NAME_INFO
    LEA SI, [BX + 8]
    LEA DI, NAME_INFO
    MOV CX, INFO_LEN
    CLD
    REP MOVSB

FINISH_PROGRAM:
    MOV AH, 4CH
    INT 21H
MAIN ENDP
END MAIN
```

## Question 4 [15 Marks]

### Q4(a) [5 Marks]
**Question:**  
*Identify the conditions that causes type 0, type 1, type 3, and type 4 interrupts. Give the importance of IF and TF flag while handling interrupts from hardware and software sources.*

#### 1. Conditions Causing Dedicated Interrupts
- **Type 0 (Divide Overflow Error):** Triggered by CPU hardware when a `DIV` or `IDIV` instruction generates a quotient that exceeds destination capacity (or division by zero).
- **Type 1 (Single-Step / Trap):** Triggered after every single instruction execution whenever the Trap Flag $\text{TF} = 1$.
- **Type 3 (Breakpoint):** Triggered by the 1-byte opcode `0CCH` (`INT 3`), used by debuggers to set breakpoints without shifting trailing code bytes.
- **Type 4 (Overflow Trap):** Triggered by the `INTO` instruction if and only if the Overflow Flag $\text{OF} = 1$.

#### 2. Importance of IF and TF during Interrupt Handling
- **Automatic Clearing:** Upon accepting any interrupt (hardware or software), the 8086 hardware **automatically clears both IF and TF**:
  - **Clearing IF ($\text{IF} \leftarrow 0$):** Disables maskable hardware interrupts (`INTR`), preventing higher-level or nested interrupts from corrupting the ISR state before the handler is ready.
  - **Clearing TF ($\text{TF} \leftarrow 0$):** Disables single-stepping inside the ISR itself, ensuring the interrupt handler executes at normal speed.

### Q4(c) [5 Marks]
**Question:**  
*Identify the difference between the following:*  
*(i) RET and IRET*  
*(ii) ENDS and ENDP*  
*(iii) GLOBAL and PUBLIC*  
*(iv) DQ and DT*  

#### 1. Detailed Comparative Analysis
1. **`RET` vs `IRET`:**
   - `RET`: Subroutine return. Pops 16-bit `IP` (near) or `IP` then `CS` (far) from stack.
   - `IRET`: Interrupt return. Pops `IP`, then `CS`, and then **pops the saved 16-bit Flags (PSW)** back into the CPU flag register.
2. **`ENDS` vs `ENDP`:**
   - `ENDS`: Assembler directive signaling the end of a **Segment** (`SEGMENT ... ENDS`) or a **Structure** (`STRUC ... ENDS`).
   - `ENDP`: Assembler directive signaling the end of a **Procedure / Subroutine** (`PROC ... ENDP`).
3. **`GLOBAL` vs `PUBLIC`:**
   - `PUBLIC`: Declares labels, variables, or procedures in the current source module to be exportable and visible to external linking modules.
   - `GLOBAL`: Used in modern assemblers/linkers to declare symbols that are both defined and exported if defined locally, or imported (`EXTRN`) if defined externally.
4. **`DQ` vs `DT`:**
   - `DQ` (Define Quadword): Allocates **8 bytes (64 bits)** of storage.
   - `DT` (Define Tenbytes): Allocates **10 bytes (80 bits)** of storage, standardly used for 18-digit packed BCD integers or 80-bit IEEE extended precision floats.

## Question 5 [15 Marks]

### Q5(a) [5 Marks]
**Question:**  
*Write an 8086 assembly language code to multiply two double word unsigned number. Store the result in consecutive memory locations of extra segment.*

#### 1. Concept: 32-bit by 32-bit Multiplication using 16-bit MUL
Let $X = (X_H \times 2^{16}) + X_L$ and $Y = (Y_H \times 2^{16}) + Y_L$.  
The 64-bit product is computed via 4 cross partial products:

$$\text{Product} = (X_L \times Y_L) + (X_L \times Y_H \times 2^{16}) + (X_H \times Y_L \times 2^{16}) + (X_H \times Y_H \times 2^{32})$$

#### 2. Assembly Program
```assembly
.MODEL SMALL
.DATA
    X_LOW   DW 1234H
    X_HIGH  DW 5678H
    Y_LOW   DW 0ABCDH
    Y_HIGH  DW 00EFH
.CODE
MAIN PROC
    MOV AX, @DATA
    MOV DS, AX
    MOV AX, 5000H       ; Extra Segment target
    MOV ES, AX
    XOR DI, DI          ; ES:DI points to destination buffer (8 bytes)

    ; Partial Product 1: X_LOW * Y_LOW
    MOV AX, X_LOW
    MUL Y_LOW           ; DX:AX = X_L * Y_L
    MOV ES:[DI+0], AX   ; Result Word 0
    MOV CX, DX          ; CX = Carry word for Word 1

    ; Partial Product 2: X_LOW * Y_HIGH
    MOV AX, X_LOW
    MUL Y_HIGH          ; DX:AX = X_L * Y_H
    ADD AX, CX          ; Add carry
    ADC DX, 0
    MOV BX, AX          ; BX = Accumulator for Word 1
    MOV BP, DX          ; BP = Carry for Word 2

    ; Partial Product 3: X_HIGH * Y_LOW
    MOV AX, X_HIGH
    MUL Y_LOW           ; DX:AX = X_H * Y_L
    ADD AX, BX          ; Accumulate into Word 1
    ADC DX, BP          ; Accumulate carry into Word 2
    MOV ES:[DI+2], AX   ; Result Word 1
    MOV BX, DX          ; BX = Word 2
    MOV CX, 0
    ADC CX, 0           ; CX = Carry for Word 3

    ; Partial Product 4: X_HIGH * Y_HIGH
    MOV AX, X_HIGH
    MUL Y_HIGH          ; DX:AX = X_H * Y_H
    ADD AX, BX
    ADC DX, CX
    MOV ES:[DI+4], AX   ; Result Word 2
    MOV ES:[DI+6], DX   ; Result Word 3

    MOV AH, 4CH
    INT 21H
MAIN ENDP
END MAIN
```

**Question:**

#### 1. Error Identification
1. `AAA DX`: **Error.** `AAA` takes no operands.
2. `SUB AL, A`: **Error.** Size mismatch error. `AL` is 8 bits; `A` is declared as word (`DW`).
3. `JNZ A`: **Error.** The target of a conditional jump must be a code label in Code Segment, not a memory variable in Data Segment.
4. `ADD A, B`: **Error.** Memory-to-memory operations are illegal in 8086 machine code.
5. `MOV [DX], AL`: **Error.** Register `DX` is illegal as a base/index pointer in memory addressing modes.

### Q5(c) [5 Marks]
**Question:**  
*Write an assembly language code to convert ten, 8 bit packed BCD number to unpacked BCD number.*

#### 1. Assembly Solution
```assembly
.MODEL SMALL
.DATA
    PACKED_BCD   DB 12H, 34H, 56H, 78H, 90H, 23H, 45H, 67H, 89H, 11H ; 10 bytes
    UNPACKED_BCD DB 20 DUP(0)                                         ; 20 bytes output
.CODE
MAIN PROC
    MOV AX, @DATA
    MOV DS, AX

    LEA SI, PACKED_BCD
    LEA DI, UNPACKED_BCD
    MOV CX, 10

UNPACK_LOOP:
    MOV AL, [SI]        ; Read packed BCD byte
    MOV AH, AL          ; Copy into AH

    ; Extract lower nibble (units digit)
    AND AL, 0FH
    MOV [DI], AL        ; Store unpacked units digit

    ; Extract upper nibble (tens digit)
    MOV AL, AH
    MOV CL, 4
    SHR AL, CL          ; Shift tens into lower nibble
    MOV [DI+1], AL      ; Store unpacked tens digit

    ADD DI, 2
    INC SI
    DEC CX
    JNZ UNPACK_LOOP

    MOV AH, 4CH
    INT 21H
MAIN ENDP
END MAIN
```

### Q6(a) [5 Marks]
**Question:**  
*Describe the paging mechanism in 80286 through Core2 microprocessors and other advance 80x86 architectures.*

#### 1. Two-Level Paging Architecture (80386 to Core 2)
Paging divides linear address space into fixed-size 4 KB pages:

$$\text{Linear Address (32 bits)} \implies [ \text{Directory (10 bits)} ] \; [ \text{Page Table (10 bits)} ] \; [ \text{Offset (12 bits)} ]$$

- **Page Directory (4 KB):** 1,024 entries pointing to page tables. Base address in `CR3`.
- **Page Table (4 KB):** 1,024 entries pointing to physical 4 KB page frames.
- **Translation Lookaside Buffer (TLB):** Hardware associative cache caching the most recent page translations, delivering 1-cycle address resolution.

#### 1. Component Functional Summary
1. **Interrupt Request Register (`IRR`):** Latches pending interrupt requests arriving on $IR_0 - IR_7$.

### Q6(d) [5 Marks]
**Question:**  
*Discuss in detail different modes of operation of 8237 DMA controller and why read and write control signals are bidirectional.*

#### 1. Operating Modes of 8237 DMAC
1. **Single Transfer Mode:** Transfers one single byte per DMA request (`DREQ`), releasing the bus after each byte.
2. **Block Transfer Mode:** Activated by `DREQ`; transfers an entire block of data until terminal count (`TC`) is reached.
3. **Demand Transfer Mode:** Continues transferring data as long as `DREQ` remains asserted active.
4. **Cascade Mode:** Allows multiple 8237 chips to be cascaded together to expand DMA channels.

#### 2. Why Control Signals ($\text{MEMR}\#, \text{MEMW}\#, \text{IOR}\#, \text{IOW}\#$) are Bidirectional
- **During CPU Programming (Slave Mode):** The 8237 is a slave peripheral. $\overline{\text{IOR}}$ and $\overline{\text{IOW}}$ act as **inputs** driven by the CPU to read status or write control parameters into 8237 registers.
- **During DMA Transfer (Bus Master Mode):** The 8237 seizes control of the system bus via `HOLD`/`HLDA`. $\overline{\text{MEMR}}, \overline{\text{MEMW}}, \overline{\text{IOR}}, \overline{\text{IOW}}$ become **outputs** driven by the 8237 to command memory and peripheral transfers directly.
