# Chapter 1: Introduction to Microprocessors and Assembly Language

## 1.1 What is a Microprocessor?
A **Microprocessor** is an integrated circuit (IC) that contains the core functions of a central processing unit (CPU) of a computer. It is driven by a clock, accepts binary data as input, processes it according to instructions stored in its memory, and provides results as output.

### The System Bus Architecture
To communicate with memory and input/output (I/O) peripherals, the microprocessor uses a collection of communication lines called a **Bus**. The system bus is divided into three distinct categories:
1. **Data Bus (Bidirectional):** Carries the actual binary data between the CPU and memory or I/O devices. A wider data bus (e.g., 16-bit vs 8-bit) allows more data to be transferred simultaneously.
2. **Address Bus (Unidirectional):** Carries the memory address or I/O port number from the CPU to the memory/peripherals. It tells the system *where* the data should go or come from. The width of the address bus determines the maximum memory capacity (e.g., 20 address lines = $2^{20} = 1\text{ MB}$).
3. **Control Bus:** Carries control signals (like Read `RD/`, Write `WR/`, Memory/IO select `IO/M/`) to coordinate and synchronize the activities of the system.

---

## 1.2 The Software Hierarchy
Microprocessors execute binary code, but humans write programs using text. Software acts as the bridge.

### Levels of Programming Languages
1. **Machine Language:** The lowest level. Consists entirely of binary $0$s and $1$s. This is the only language the microprocessor actually understands.
2. **Assembly Language:** A low-level programming language where machine instructions are represented by readable abbreviations called **Mnemonics** (e.g., `MOV`, `ADD`, `JMP`).
3. **High-Level Language:** Human-readable code (like C, C++, Python) that abstracts away hardware details.

### System Software & Translators
To convert human code into machine code, the computer uses translators:
* **Assembler:** Translates Assembly Language code (mnemonics) directly into Machine Language (binary object code).
* **Compiler / Interpreter:** Translates High-Level Language into Machine Language.
* **Linker (Linkage Editor):** Takes one or more object files generated by a compiler or assembler and combines them into a single executable program.
* **Resident Monitor / Operating System:** The core program that is always loaded in memory to handle I/O and execute user programs.

---

## 1.3 Features of Assembly Language Programming
Writing programs in Assembly language gives you absolute control over the microprocessor.

1. **Machine Dependent:** Assembly code is tied directly to the specific architecture of the CPU. Code written for an x86 processor (like the 8086) will not run on an ARM processor.
2. **Low-Level Language:** It is one step above machine code. You manage the exact memory locations and CPU registers.
3. **Mnemonic Instructions:** Uses short, readable operation codes (e.g., `SUB` for subtract) instead of raw binary hex values.
4. **Fast Execution & High Performance:** Since there is no heavy overhead from high-level abstractions, assembly programs execute incredibly fast.
5. **Efficient Memory Usage:** Programmers have direct control over exactly how many bytes are used, preventing memory bloat.
6. **Direct Hardware Access:** Capable of interacting directly with I/O ports and specific memory addresses to control peripheral devices (like timers or displays).
7. **Register-Based Operations:** Most computations avoid slow RAM by performing math directly inside the CPU's internal high-speed memory cells (Registers).
8. **Limited Portability:** Code must be rewritten if migrating to a different CPU family.

---

## 1.4 Common Assembly Development Tools
To write, assemble, and debug x86 Assembly code, several software environments and toolchains are commonly used in academia and industry:

* **MASM (Microsoft Macro Assembler):** Microsoft's assembler for the x86 architecture. Highly popular in legacy DOS/Windows environments.
* **NASM (Netwide Assembler):** A free, open-source assembler widely used today. It supports a variety of output formats (Linux, Windows, macOS).
* **TASM (Turbo Assembler):** Developed by Borland, popular in educational environments alongside Turbo C/C++.
* **DOSBox-X / EMU8086 (Emulator):** Since modern 64-bit operating systems do not natively run 16-bit DOS programs, an emulator like DOSBox or EMU8086 is required to safely simulate the 8086 microprocessor environment.
* **SASM (SimpleASM IDE):** A modern, open-source Integrated Development Environment (IDE) specifically designed for NASM, MASM, GAS, and FASM. It provides syntax highlighting and a built-in debugger.

### Example: A Basic Assembly Program Structure
If you are writing complete code, your file will typically have segments defined for data and code.

```assembly
; A typical complete code structure in MASM/TASM

DATA SEGMENT           ; Define the start of the data segment
    NUM1 DB 05H        ; DB = Define Byte. Variable NUM1 initialized to 05H
    NUM2 DB 03H        ; Variable NUM2 initialized to 03H
    RESULT DB ?        ; Uninitialized byte to store the answer
DATA ENDS              ; End of data segment

CODE SEGMENT           ; Define the start of the code segment
    ASSUME CS:CODE, DS:DATA  ; Tell the assembler which segments to use

START: 
    MOV AX, DATA       ; Initialize Data Segment register (DS)
    MOV DS, AX         ; DS cannot be loaded directly with immediate data

    MOV AL, NUM1       ; Load the value of NUM1 into register AL
    ADD AL, NUM2       ; Add the value of NUM2 to AL. (AL = AL + NUM2)
    MOV RESULT, AL     ; Store the final sum from AL into memory variable RESULT

    MOV AH, 4CH        ; Setup DOS interrupt to terminate program gracefully
    INT 21H            ; Call DOS interrupt
CODE ENDS              ; End of code segment

END START              ; End of file, specify the entry point 'START'
```

# Chapter 2: The 8085 Microprocessor Deep Dive

## 2.1 The 8085 Microprocessor: Overview and Architecture
The Intel 8085 is an 8-bit microprocessor introduced in the late 1970s. While modern computers use 64-bit processors, studying the 8085 is fundamental for understanding how the core principles of CPU architecture work.

### Main Technical Specifications
* **Data Bus:** 8-bit. It can process 8 bits of data simultaneously.
* **Address Bus:** 16-bit. It can address up to $2^{16} = 65,536\text{ bytes}$ ($64\text{ KB}$) of memory.
* **Clock Speed:** Typically runs at $3\text{ MHz}$ (8085A) or $5\text{ MHz}$ (8085A-2).
* **Power Supply:** Single $+5\text{V}$ power supply.
* **Instruction Set:** Contains exactly 80 machine instructions.

### Pin Functions and Hardware Signals
The 8085 chip communicates with the outside world via 40 pins. Key signals include:
1. **`X1` and `X2`:** Input pins connected to an external crystal oscillator to provide the clock rhythm.
2. **`SID` (Serial Input Data) & `SOD` (Serial Output Data):** Used for single-bit serial communication. Manipulated via the `RIM` (Read Interrupt Mask) and `SIM` (Set Interrupt Mask) instructions.
3. **`AD0 - AD7` (Multiplexed Address/Data Bus):** To save physical pins on the chip, these 8 lines serve a dual purpose. During the first clock cycle ($T_1$), they transmit the lower 8 bits of the memory address. During subsequent cycles ($T_2, T_3$), they switch roles to transfer actual data.
4. **`A8 - A15` (Address Bus):** An 8-bit unidirectional bus that always carries the higher-order 8 bits of the memory address.
5. **`ALE` (Address Latch Enable):** Because `AD0-AD7` switches roles between Address and Data, the CPU sends a positive pulse on the `ALE` pin during $T_1$. This signals external latches (hardware memory buffers) to capture and hold the address before the lines switch to data mode.
6. **`IO/M/` (Input/Output / Memory Select):** A signal that tells the external circuitry whether the CPU is trying to talk to RAM (Memory Mode, active low) or a peripheral device (I/O Mode, active high).
7. **`READY`:** An input pin. If the CPU is communicating with a slow memory chip, the memory can pull `READY` low, forcing the CPU to pause (enter WAIT states) until the slow memory catches up.
8. **`HOLD` and `HLDA` (Hold Acknowledge):** Used for Direct Memory Access (DMA). An external device requests control of the buses by asserting `HOLD`. The CPU finishes its current cycle and responds with `HLDA`, disconnecting itself from the buses so the device can transfer data directly to RAM.

---

## 2.2 Register Organization (The CPU's Internal Memory)
Registers are ultra-fast, temporary storage pockets located directly inside the CPU.

### General Purpose Registers (8-bit)
The 8085 has six 8-bit general-purpose registers: **B, C, D, E, H, and L**.
Because a memory address is 16 bits long, these 8-bit registers can be paired up to form 16-bit pairs to hold addresses:
* **`BC` Pair**
* **`DE` Pair**
* **`HL` Pair:** This is the most important pair. The `HL` pair is primarily used as the default **Memory Pointer** (Data Pointer). When an instruction targets the abstract memory register `M`, the CPU looks at the 16-bit address held in the `HL` pair to know where in RAM to go.

### Special Purpose Registers
1. **Accumulator (`A` Register, 8-bit):** The most important register. All math and logic operations (Addition, Subtraction, AND, OR) are performed here. The final result is also stored back in the Accumulator.
2. **Flag Register (8-bit):** Holds 5 individual bits (Flags) that act as a dashboard warning light to report the status of the last arithmetic operation:
    * **`S` (Sign Flag):** Set to 1 if the result is negative (MSB is 1).
    * **`Z` (Zero Flag):** Set to 1 if the result is exactly zero.
    * **`AC` (Auxiliary Carry Flag):** Used internally for BCD (Binary Coded Decimal) math. Set if there is a carry from bit 3 to bit 4.
    * **`P` (Parity Flag):** Set to 1 if the binary result contains an even number of `1`s (Even Parity).
    * **`CY` (Carry Flag):** Set to 1 if the math operation resulted in an overflow or required a borrow.
3. **Stack Pointer (`SP`, 16-bit):** Points to the top of the Stack (a temporary LIFO storage area in RAM).
4. **Program Counter (`PC`, 16-bit):** Holds the exact memory address of the *next* instruction the CPU needs to fetch. Automatically increments after every fetch.

---

## 2.3 Addressing Modes in 8085
"Addressing Mode" simply means "How do we tell the CPU where to find the data for this instruction?" The 8085 has five modes:

1. **Immediate Addressing:** The data is hardcoded directly inside the instruction itself.
   ```assembly
   MVI A, 45H    ; Move Immediate: Load the hex value 45 directly into Accumulator A
   ```
2. **Register Addressing:** The data is already in a CPU register.
   ```assembly
   MOV B, A      ; Copy the contents of Register A into Register B
   ```
3. **Direct Addressing:** The 16-bit memory address of the data is explicitly stated in the instruction.
   ```assembly
   LDA 2050H     ; Load Accumulator directly from memory address 2050 Hex
   ```
4. **Register Indirect Addressing:** The CPU looks inside a register pair (like `HL`) to find the memory address, then goes to that address to get the data.
   ```assembly
   MOV A, M      ; Move to A from Memory. (Memory address is defined by the HL pair)
   ```
5. **Implied (Implicit) Addressing:** The instruction doesn't need an operand because the target is understood (usually the Accumulator).
   ```assembly
   CMA           ; Complement Accumulator: Invert all bits in Register A
   ```

---

## 2.4 Interrupt Processing & The 8259 PIC
An interrupt is a hardware signal sent to the CPU, telling it to pause its current program and execute an emergency subroutine (Interrupt Service Routine - ISR). 

The 8085 has 5 hardware interrupt pins, ranked by strict priority:

| Interrupt Line | Trigger Type | Priority | Vector Address (Hex) | Maskable? |
| :--- | :--- | :--- | :--- | :--- |
| **`TRAP` (RST 4.5)** | Edge AND Level | 1 (Highest) | `0024H` | Non-Maskable |
| **`RST 7.5`** | Rising Edge | 2 | `003CH` | Maskable via `SIM` |
| **`RST 6.5`** | High Level | 3 | `0034H` | Maskable via `SIM` |
| **`RST 5.5`** | High Level | 4 | `0020H` | Maskable via `SIM` |
| **`INTR`** | High Level | 5 (Lowest) | Provided by external IC | Maskable via `EI`/`DI` |

### How Hardware Interrupts Work
1. **TRAP:** This is an absolute emergency (e.g., power failure). It is "Non-Maskable" meaning no software command can ignore it. It instantly forces the CPU to jump to memory address `0024H`.
2. **RST (Restart) 7.5, 6.5, 5.5:** These are "Vectored" interrupts. When triggered, the CPU calculates a specific mathematical address (the Vector) and jumps there. You can disable (Mask) them using the `SIM` (Set Interrupt Mask) instruction.
   * *Formula to calculate Vector Address:* `Vector Address = N x 8`
   * *Example for RST 5.5:* $5.5 \times 8 = 44_{10}$. Convert 44 to Hexadecimal = `002CH`.
3. **INTR (Handshake Interrupt):** The lowest priority. It is "Non-Vectored," meaning it doesn't have a hardcoded jump address.

### The 8259 Programmable Interrupt Controller (PIC)
Because the 8085 only has a few interrupt pins, computers use an external chip (the **8259 PIC**) to manage multiple devices (keyboard, mouse, hard drive) trying to interrupt the CPU simultaneously.
* The 8259 can accept up to 8 external interrupts (`IR0` to `IR7`).
* It checks priority. If `IR1` and `IR4` trigger at the same time, it serves the highest priority first.
* It sends a single `INTR` signal to the 8085.
* The 8085 responds with `INTA/` (Interrupt Acknowledge).
* The 8259 then places the appropriate `CALL` opcode and 16-bit subroutine address directly onto the data bus so the 8085 knows exactly where to jump to handle the device.

# Chapter 3: 8086 Architecture and Memory Management

## 3.1 Overview of the 8086 Microprocessor
The Intel 8086 is a monumental upgrade over the 8085. It is a true 16-bit microprocessor designed to handle significantly more data and larger programs.

### Key Technical Features
* **Data Bus:** 16-bit. It can read or write a full 16-bit Word in a single operation.
* **Address Bus:** 20-bit. It can address up to $2^{20} = 1,048,576\text{ bytes}$ ($1\text{ MB}$) of physical memory.
* **I/O Ports:** Supports up to $64\text{K}$ ($65,536$) separate Input/Output ports.
* **Registers:** Fourteen 16-bit registers.
* **Power & Clock:** Requires a single $+5\text{V}$ supply and operates between $5\text{ MHz}$ and $8\text{ MHz}$.
* **Operating Modes:** Can operate in **Minimum Mode** (single processor system) or **Maximum Mode** (multi-processor system with coprocessors like the 8087 math chip).

---

## 3.2 The Two-Unit Architecture: BIU and EU
To drastically speed up execution, the 8086 is internally divided into two completely separate processing units that work in parallel. This overlapping of fetching and executing is known as **Pipelining**.

### 1. The Bus Interface Unit (BIU)
The BIU handles all communication with the outside world (the buses). 
* **Responsibilities:** Fetching instructions from memory, reading/writing operands, and calculating physical memory addresses.
* **The Instruction Queue (Q):** To prevent the Execution Unit from waiting for memory reads, the BIU "looks ahead." When the buses are idle, the BIU prefetches up to **6 bytes** of upcoming instructions and stores them in a First-In-First-Out (FIFO) queue.
* **Components:** Contains the Segment Registers, the Instruction Pointer (IP), the Queue, and the Address Summing Block.

### 2. The Execution Unit (EU)
The EU does the actual brainwork. It does *not* connect to the system buses directly.
* **Responsibilities:** Decodes instructions pulled from the BIU's Queue, generates control signals, and performs arithmetic/logic via the ALU (Arithmetic Logic Unit).
* **Components:** Contains the General Purpose Registers, Index/Pointer Registers, the Flag Register, and the ALU.

---

## 3.3 The 8086 Register Set
The 8086 provides 14 internal 16-bit registers.

### General Purpose Registers
These can be used as full 16-bit registers or split into two independent 8-bit registers (High and Low).
1. **`AX` (Accumulator Register - `AH` & `AL`):** Primary register for arithmetic, logic, and data transfer. Multiplication and division instructions *force* the use of AX.
2. **`BX` (Base Register - `BH` & `BL`):** Frequently used to hold the base address of data structures (like arrays) in memory.
3. **`CX` (Count Register - `CH` & `CL`):** Automatically used by the hardware as a countdown timer for looping instructions (`LOOP`) and bit shift/rotate operations.
4. **`DX` (Data Register - `DH` & `DL`):** Used to hold the upper 16 bits in 32-bit multiplication/division, and holds the port address for I/O operations (`IN`, `OUT`).

### Pointer and Index Registers
Always 16-bit. They hold memory offsets (relative addresses).
1. **`SP` (Stack Pointer):** Points to the current top of the stack.
2. **`BP` (Base Pointer):** Used to access data inside the stack, usually parameters passed into subroutines.
3. **`SI` (Source Index):** Points to the source string/array in string operations.
4. **`DI` (Destination Index):** Points to the destination string/array in string operations.

### The Flag Register (Status & Control)
A 16-bit register where 9 bits are active. 
**Status Flags (Math Results):**
* **`CF` (Carry Flag):** Set if an addition produces a carry or subtraction needs a borrow.
* **`PF` (Parity Flag):** Set if the lower 8 bits of the result have an even number of `1`s.
* **`AF` (Auxiliary Carry):** Carry from bit 3 to bit 4 (used for BCD math).
* **`ZF` (Zero Flag):** Set to 1 if the result is exactly zero.
* **`SF` (Sign Flag):** Set to 1 if the result is negative (MSB is 1).
* **`OF` (Overflow Flag):** Set if signed arithmetic exceeds the register's capacity (e.g., adding two positive numbers results in a negative number).

**Control Flags (Hardware Behavior):**
* **`TF` (Trap Flag):** If set, CPU enters single-step debugging mode, executing one instruction at a time.
* **`IF` (Interrupt Flag):** If set (`STI`), maskable hardware interrupts (`INTR`) are enabled. If cleared (`CLI`), they are disabled.
* **`DF` (Direction Flag):** Controls string operations. If 0 (`CLD`), string pointers (`SI`/`DI`) auto-increment (forward). If 1 (`STD`), they auto-decrement (backward).

---

## 3.4 Segmented Memory Architecture
The 8086 has 20 address pins, allowing $1\text{ MB}$ of memory. However, the internal registers (`IP`, `BX`, `SI`, etc.) are only 16 bits wide, meaning they can only count up to $65,535$ ($64\text{ KB}$). 

To solve this, memory is divided into $64\text{ KB}$ blocks called **Segments**. The CPU addresses memory by combining a **Segment Base Address** with a 16-bit **Offset**.

### The 4 Segment Registers
1. **`CS` (Code Segment):** Holds the base address for the running program's instructions.
2. **`DS` (Data Segment):** Holds the base address for the program's variables.
3. **`SS` (Stack Segment):** Holds the base address for the stack.
4. **`ES` (Extra Segment):** Usually serves as a secondary data segment, specifically for the destination in string operations.

### Physical Address Calculation
Inside the BIU, a dedicated hardware adder (the Address Summing Block) calculates the true 20-bit physical address using this formula:

$$\text{Physical Address} = (\text{Segment Register} \times 16_{10}) + \text{Offset Register}$$
*(In Hexadecimal: Multiply the Segment by `10H` (shift left 1 hex digit), then add the Offset)*

**Example Calculation:**
If the Data Segment (`DS`) is `4000H` and the Base Register (`BX`) offset is `0150H`:
* Shift DS left: `4000H` $\rightarrow$ `40000H`
* Add Offset: `40000H` + `0150H` = **`40150H`** (This is the exact byte in the 1MB RAM).

---

## 3.5 The 7 Addressing Modes of 8086
How does the CPU know *where* an operand is? It relies on the Addressing Mode.

1. **Register Addressing:** Data is in an internal register. (Fastest, no memory access).
   ```assembly
   MOV AX, BX       ; Copy 16-bit contents of BX into AX
   ```
2. **Immediate Addressing:** The actual data value is hardcoded into the instruction.
   ```assembly
   MOV CX, 2550H    ; Load the literal hex value 2550 into CX
   ```
   > [!WARNING] 
   > You **cannot** load immediate data directly into a Segment Register. `MOV DS, 1000H` is illegal. You must go through a general register: `MOV AX, 1000H` then `MOV DS, AX`.
3. **Direct Addressing:** The 16-bit offset address is hardcoded in brackets.
   ```assembly
   MOV AL, [2400H]  ; Fetch the byte from offset 2400H in the Data Segment
   ```
4. **Register Indirect Addressing:** The offset address is held inside `BX`, `BP`, `SI`, or `DI`.
   ```assembly
   MOV AX, [BX]     ; Fetch the word from memory at the offset stored in BX
   ```
5. **Base Relative Addressing:** Offset = Base Register (`BX` or `BP`) + an 8/16-bit displacement.
   ```assembly
   MOV AL, [BX + 5] ; Fetch byte from memory at offset (BX + 5)
   ```
6. **Indexed Relative Addressing:** Offset = Index Register (`SI` or `DI`) + an 8/16-bit displacement. Used heavily for array traversal.
   ```assembly
   MOV DX, ARRAY[SI]; Fetch data from offset (ARRAY_Base + SI)
   ```
7. **Base Indexed Relative Addressing:** The ultimate flexible mode. Offset = Base + Index + Displacement. Excellent for 2D arrays.
   ```assembly
   MOV AX, [BX + SI + 10H] ; Fetch word from offset (BX + SI + 16 decimal)
   ```

---

## 3.6 Machine Instruction Format Encoding
When you write `MOV CX, BX`, the assembler translates it into binary machine code. 8086 instructions range from 1 to 6 bytes. A typical instruction byte is structured as:
* **Opcode (6 bits):** Identifies the operation (e.g., `100010` = `MOV`).
* **`D` (Direction Bit, 1 bit):** 
  * `0`: Data flows *from* the specified `REG` to the `R/M` location.
  * `1`: Data flows *to* the specified `REG` from the `R/M` location.
* **`W` (Word/Byte Bit, 1 bit):** 
  * `0`: 8-bit Byte operation.
  * `1`: 16-bit Word operation.
* **`MOD` (Mode Field, 2 bits) & `R/M` (Register/Memory, 3 bits):** Together these 5 bits dictate which of the 7 addressing modes is being used, and whether there is an 8-bit or 16-bit displacement attached.
* **`REG` (Register Field, 3 bits):** Dictates exactly which register (`AX`, `BX`, etc.) is involved.

# Chapter 4: 8086 Instruction Set Basics

The 8086 supports over 20,000 instruction variations. To understand them, we classify them into logical groups.

## 4.1 General Assembler Instruction Syntax
Every assembly instruction follows a strict format:
```assembly
Label:   Mnemonic   Destination, Source   ; Comments
```
If an instruction interacts with memory and the size (byte vs word) is ambiguous, the Assembler will throw an error. You must explicitly define the size using the `PTR` (Pointer) operator.
```assembly
INC [BX]               ; ERROR: Ambiguous! Are we incrementing a byte or a 16-bit word?
INC BYTE PTR [BX]      ; Correct: Increments the 8-bit byte at memory address [BX]
INC WORD PTR [BX]      ; Correct: Increments the 16-bit word at memory address [BX]
```

---

## 4.2 Data Transfer Instructions
These instructions move data. **Critical Rule: Data transfer instructions NEVER affect the Status Flags.**

### `MOV` (Move Data)
Copies data from Source to Destination.
```assembly
MOV AX, 1234H          ; Load immediate word into AX
MOV BX, AX             ; Copy AX into BX
MOV CX, [5000H]        ; Load word from memory address 5000H into CX
```
*Constraints:* You **cannot** move memory to memory directly (e.g., `MOV [1000H], [2000H]` is invalid). You **cannot** move immediate data directly into a Segment Register (e.g., `MOV DS, 1000H` is invalid).

### `XCHG` (Exchange)
Swaps the contents of two operands. At least one must be a register. Segment registers cannot be exchanged.
```assembly
XCHG AX, BX            ; Swap AX and BX
XCHG AL, [1000H]       ; Swap AL with the memory byte at 1000H
```

### Pointer Loading: `LEA`, `LDS`, `LES`
These instructions deal with memory addresses (pointers) rather than raw numerical data.
* **`LEA` (Load Effective Address):** Calculates the offset address of a memory variable and loads *the address itself* into a register, not the data at the address.
  ```assembly
  LEA BX, ARRAY        ; BX now holds the 16-bit memory address of ARRAY
  ```
* **`LDS` (Load Pointer to DS) & `LES` (Load Pointer to ES):** Loads a full 32-bit far pointer (Segment + Offset) from memory into a designated register AND a segment register.
  ```assembly
  LDS SI, [0301H]      ; Loads the 16-bit offset into SI, and the 16-bit Segment into DS
  LES DI, [POINTER]    ; Loads offset into DI, Segment into ES
  ```

---

## 4.3 Arithmetic Instructions
Arithmetic operations **always affect the Status Flags** (CF, PF, AF, ZF, SF, OF) depending on the result, with a few notable exceptions.

### Addition and Subtraction
* **`ADD` / `SUB`:** Standard addition and subtraction.
* **`ADC` (Add with Carry) / `SBB` (Subtract with Borrow):** Includes the current state of the Carry Flag in the calculation. Vital for multi-word math (like adding two 32-bit numbers in a 16-bit system).
  ```assembly
  ADD AX, BX           ; AX = AX + BX
  ADC DX, CX           ; DX = DX + CX + Carry Flag
  SUB AX, 0005H        ; AX = AX - 5
  SBB BX, CX           ; BX = BX - CX - Carry Flag
  ```

### Increment, Decrement, and Negation
* **`INC` / `DEC`:** Adds or subtracts 1. 
  > [!IMPORTANT] 
  > **CRITICAL RULE:** `INC` and `DEC` affect all flags **EXCEPT** the Carry Flag (`CF`). This allows you to increment loop counters without destroying the carry state from a previous addition.
  ```assembly
  INC CX               ; CX = CX + 1
  DEC BYTE PTR [SI]    ; Decrement the memory byte pointed to by SI
  ```
* **`NEG`:** Performs Two's Complement negation (multiplies by -1).
  ```assembly
  NEG AL               ; If AL was 5, it becomes -5 (Two's Complement binary)
  ```

### Compare and Sign Extension
* **`CMP` (Compare):** Exactly the same as `SUB`, but it **throws away the result**. It is used purely to set the Status Flags so a conditional Jump can be performed immediately after.
  ```assembly
  CMP AX, BX           ; Internally calculates AX - BX and sets flags, but AX remains untouched.
  ```
* **`CBW` (Convert Byte to Word) & `CWD` (Convert Word to Doubleword):** Extends the sign bit of a number so 8-bit math can be safely expanded into 16-bit math. **Affects NO flags.**
  ```assembly
  MOV AL, -5           ; AL holds 8-bit negative 5
  CBW                  ; Expands AL into AX by copying the sign bit into AH. AX now holds 16-bit -5.
  ```

### Multiplication and Division
Multiplication and Division have rigid register requirements. You cannot use immediate data (e.g., `MUL 5` is illegal).
* **`MUL` (Unsigned) & `IMUL` (Signed Multiplication):** 
  * *8-bit multiply:* `AL` is implicitly multiplied by the operand. Result goes to `AX`.
  * *16-bit multiply:* `AX` is implicitly multiplied by the operand. Result goes to `DX:AX` (DX holds high 16 bits, AX holds low 16 bits).
  ```assembly
  MUL BL               ; AX = AL * BL (Unsigned)
  IMUL CX              ; DX:AX = AX * CX (Signed)
  ```
* **`DIV` (Unsigned) & `IDIV` (Signed Division):**
  * *8-bit divide:* `AX` divided by operand. Quotient in `AL`, Remainder in `AH`.
  * *16-bit divide:* `DX:AX` divided by operand. Quotient in `AX`, Remainder in `DX`.
  ```assembly
  DIV BL               ; AX / BL -> Quotient in AL, Remainder in AH
  ```

---

## 4.4 Logical and Bit Manipulation Instructions
Logical instructions perform bitwise Boolean algebra. **They always force CF=0 and OF=0**, and update SF, ZF, and PF based on the result.

* **`AND`, `OR`, `XOR`:** Standard bitwise operations. Used for masking, setting, or toggling specific bits.
  ```assembly
  AND AL, 0FH          ; Clears upper 4 bits, keeps lower 4 bits
  OR  BL, 80H          ; Forces the MSB (bit 7) to 1
  XOR CX, CX           ; Fastest way to clear a register to 0 (CX = 0)
  ```
* **`NOT`:** Inverts all bits (One's Complement). **Does NOT affect any flags.**
* **`TEST`:** Exactly like `AND`, but throws away the result. Used purely to set flags to test if a specific bit is a 1 or 0.

### Shift and Rotate Instructions
Used to move bits left or right. The `CF` (Carry Flag) acts as an extra 17th bit that catches bits pushed out the end. The count must be `1`, or stored in the `CL` register.

* **`SHL` / `SAL` (Shift Left):** Multiplies by 2. Pushes 0 in from the right. MSB goes to Carry Flag.
* **`SHR` (Shift Logical Right):** Divides unsigned numbers by 2. Pushes 0 in from the left. LSB goes to Carry Flag.
* **`SAR` (Shift Arithmetic Right):** Divides signed numbers by 2. **Retains the original sign bit** by copying it back into the MSB, preserving negativity. LSB goes to CF.
* **`ROL` / `ROR` (Rotate Left / Right):** Bits pushed out one end wrap around and enter the other end, while ALSO copying into the Carry Flag.
* **`RCL` / `RCR` (Rotate through Carry):** Includes the Carry Flag in the rotation ring, effectively making it a 9-bit or 17-bit rotation.
  ```assembly
  SHL AX, 1            ; Shift AX left by 1 bit
  MOV CL, 4            
  ROR BX, CL           ; Rotate BX right by 4 bits (CL is required for count > 1)
  ```

# Chapter 5: 8086 Advanced Instructions (Branching, Strings, and Stacks)

## 5.1 Branching and Flow Control
Normally, the CPU executes instructions sequentially by automatically incrementing the Instruction Pointer (`IP`). Branching instructions force the `IP` to load a new address, jumping to a different part of the code.

### Unconditional Jumps
* **`JMP Target_Label`:** Immediately jumps to the specified label. No flags are checked, and no flags are affected.
  ```assembly
  START: 
      MOV AX, 0000H
      JMP START        ; Infinite loop back to START
  ```

### Conditional Jumps
These jumps check the current state of the Status Flags (usually set by a previous `CMP` or arithmetic instruction). If the condition is met, it jumps. If not, it falls through to the next instruction.
* **`JZ` / `JE` Target:** Jump if Zero / Jump if Equal. (Jumps if `ZF = 1`)
* **`JNZ` / `JNE` Target:** Jump if Not Zero / Jump if Not Equal. (Jumps if `ZF = 0`)
* **`JC` / `JB` Target:** Jump if Carry / Jump if Below. (Jumps if `CF = 1`)
* **`JNC` / `JAE` Target:** Jump if No Carry / Jump if Above or Equal. (Jumps if `CF = 0`)
* **`JS` Target:** Jump if Sign (Negative). (Jumps if `SF = 1`)
* **`JNS` Target:** Jump if No Sign (Positive). (Jumps if `SF = 0`)

**Complete Code Example: Finding the Maximum of Two Numbers**
```assembly
DATA SEGMENT
    NUM1 DB 45H
    NUM2 DB 8AH
    MAX  DB ?
DATA ENDS

CODE SEGMENT
    ASSUME CS:CODE, DS:DATA
START:
    MOV AX, DATA
    MOV DS, AX

    MOV AL, NUM1       ; Load first number
    MOV BL, NUM2       ; Load second number
    CMP AL, BL         ; Compare AL and BL (Internally: AL - BL)
    JC SECOND_IS_BIGGER ; If AL < BL, subtraction requires a borrow, setting Carry Flag (CF=1)

    ; If we reach here, AL >= BL
    MOV MAX, AL        ; Store NUM1 as maximum
    JMP FINISH         ; Skip the next block

SECOND_IS_BIGGER:
    MOV MAX, BL        ; Store NUM2 as maximum

FINISH:
    MOV AH, 4CH        ; DOS terminate
    INT 21H
CODE ENDS
END START
```

---

## 5.2 Looping Mechanics
To execute a block of code multiple times, the 8086 uses the `CX` (Count Register) alongside dedicated `LOOP` instructions.

* **`LOOP Target`:** When executed, the CPU automatically decrements `CX` by 1. If `CX` is not zero, it jumps to `Target`. If `CX` is zero, the loop ends.
  > [!TIP]
  > The hardware specifically designs `LOOP` so that **it does not affect any flags**. This is crucial, as you usually have math happening inside the loop that needs the flags preserved.

**Complete Code Example: Adding 5 Numbers in an Array**
```assembly
DATA SEGMENT
    ARRAY DB 10H, 20H, 30H, 40H, 50H
    SUM   DB 0
DATA ENDS

CODE SEGMENT
    ASSUME CS:CODE, DS:DATA
START:
    MOV AX, DATA
    MOV DS, AX

    LEA SI, ARRAY      ; Load offset of ARRAY into Source Index
    MOV CX, 0005H      ; Set loop counter to 5
    MOV AL, 00H        ; Clear AL to hold the running total

ADD_LOOP:
    ADD AL, [SI]       ; Add the current array element to AL
    INC SI             ; Point to the next element
    LOOP ADD_LOOP      ; Decrement CX. If CX != 0, jump back to ADD_LOOP

    MOV SUM, AL        ; Store final sum

    MOV AH, 4CH
    INT 21H
CODE ENDS
END START
```

---

## 5.3 Hardware String Primitives
Moving large blocks of memory (arrays/strings) byte-by-byte using loops is slow. The 8086 has dedicated hardware "String Primitives" that act like conveyor belts.

### The Strict Rules of String Operations
1. **Source:** MUST be pointed to by `DS:SI` (Data Segment : Source Index).
2. **Destination:** MUST be pointed to by `ES:DI` (Extra Segment : Destination Index).
3. **Direction:** Controlled by the Direction Flag (`DF`).
   * `CLD` (Clear Direction): `DF = 0`. Pointers (`SI`/`DI`) auto-increment (move forward).
   * `STD` (Set Direction): `DF = 1`. Pointers auto-decrement (move backward).

### The String Instructions
* **`MOVSB` / `MOVSW` (Move String Byte/Word):** Copies a byte/word from `[DS:SI]` to `[ES:DI]`, then auto-updates `SI` and `DI`.
* **`CMPSB` / `CMPSW` (Compare String):** Compares byte/word at `[DS:SI]` with `[ES:DI]` and updates flags.
* **`SCASB` / `SCASW` (Scan String):** Searches for a specific character. Compares the Accumulator (`AL`/`AX`) with the memory at `[ES:DI]`.
* **`LODSB` / `LODSW` (Load String):** Copies memory at `[DS:SI]` into the Accumulator (`AL`/`AX`).
* **`STOSB` / `STOSW` (Store String):** Copies the Accumulator (`AL`/`AX`) into memory at `[ES:DI]`.

### The `REP` Prefix
You can attach a `REP` (Repeat) prefix to string instructions. It tells the CPU to automatically repeat the instruction `CX` times, effectively turning a single instruction into an ultra-fast hardware loop.

**Complete Code Example: Copying a String**
```assembly
DATA SEGMENT
    SOURCE_STR DB 'HELLO WORLD'
    DEST_STR   DB 11 DUP(?)     ; Allocate 11 bytes of uninitialized space
DATA ENDS

EXTRA_SEG SEGMENT                 ; Define Extra Segment for string destination
EXTRA_SEG ENDS

CODE SEGMENT
    ASSUME CS:CODE, DS:DATA, ES:EXTRA_SEG
START:
    MOV AX, DATA
    MOV DS, AX
    MOV AX, EXTRA_SEG
    MOV ES, AX         ; Initialize Extra Segment

    LEA SI, SOURCE_STR ; Setup Source Pointer (DS:SI)
    LEA DI, DEST_STR   ; Setup Destination Pointer (ES:DI)
    MOV CX, 000BH      ; String length is 11 bytes (0BH)

    CLD                ; Clear Direction Flag to move forward

    REP MOVSB          ; Repeat "Move String Byte" CX times!

    MOV AH, 4CH
    INT 21H
CODE ENDS
END START
```

## 5.4 The Stack and Modular Programming
The Stack is a Last-In, First-Out (LIFO) temporary memory structure. It grows "upside down" in memory—meaning as you add items, the memory address decreases.

* **`PUSH Source`:** Subtracts 2 from the Stack Pointer (`SP`), then writes a 16-bit word to `[SS:SP]`. You cannot push 8-bit bytes, only 16-bit words.
* **`POP Destination`:** Reads a 16-bit word from `[SS:SP]` into the destination, then adds 2 to the Stack Pointer.

### Procedures (`CALL` and `RET`)
Procedures (functions/subroutines) allow you to write reusable code blocks.

* **`CALL Procedure_Name`:** 
  1. The CPU takes the address of the *next* instruction (the return address) and `PUSH`es it onto the stack to save it.
  2. The CPU jumps to the `Procedure_Name`.
* **`RET` (Return):**
  1. The CPU `POP`s the saved return address off the stack and loads it back into the Instruction Pointer (`IP`).
  2. Execution resumes right after the original `CALL`.

**Complete Code Example: Reusable Procedure**
```assembly
DATA SEGMENT
    NUM1 DW 1234H
    NUM2 DW 5678H
DATA ENDS

CODE SEGMENT
    ASSUME CS:CODE, DS:DATA
START:
    MOV AX, DATA
    MOV DS, AX

    MOV AX, NUM1       ; Load first parameter
    MOV BX, NUM2       ; Load second parameter

    CALL SWAP_REGS     ; Call the subroutine. Hardware pushes return address to Stack.

    ; At this point, AX will be 5678H and BX will be 1234H
    MOV AH, 4CH
    INT 21H

; ---------------------------------
; Procedure: SWAP_REGS
; Purpose: Swaps contents of AX and BX
; ---------------------------------
SWAP_REGS PROC NEAR
    PUSH CX            ; Save CX so we don't destroy its original value
    
    MOV CX, AX         ; Temp = AX
    MOV AX, BX         ; AX = BX
    MOV BX, CX         ; BX = Temp
    
    POP CX             ; Restore CX's original value
    RET                ; Pop return address to IP and go back to main program
SWAP_REGS ENDP

CODE ENDS
END START
```

# Chapter 6: Assembler Directives

Directives (also called Pseudo-Operations) are instructions for the Assembler program itself (like MASM or TASM), not for the microprocessor. They do not generate machine code instructions for the CPU to execute. Instead, they tell the assembler how to allocate memory, organize segments, and evaluate mathematical expressions.

---

## 6.1 Data Definition and Storage Allocation
These directives allocate physical bytes in RAM and initialize them with data.

* **`DB` (Define Byte):** Allocates 8-bit memory.
* **`DW` (Define Word):** Allocates 16-bit memory.
* **`DD` (Define Doubleword):** Allocates 32-bit memory.

### Complete Examples of Data Allocation
```assembly
DATA SEGMENT
    ; Defining simple numeric variables
    DATA_BYTE   DB 10, 4, 10H        ; Allocates 3 bytes: decimal 10, decimal 4, hex 10
    DATA_WORD   DW 100, 100H, -5     ; Allocates 3 words (6 bytes total)
    DATA_DWORD  DD 3*20, 0FFFDH      ; Allocates 2 doublewords. Evaluates 3*20 at compile time.

    ; Defining strings
    MESSAGE1    DB 'H', 'E', 'L', 'L', 'O' ; 5 bytes
    MESSAGE2    DB 'HELLO'                 ; Exactly identical to MESSAGE1

    ; Uninitialized Data
    ABC         DB 0, ?, ?, ?, 0     ; '?' means allocate 1 byte but leave it uninitialized
    DEF         DW ?, 52, ?          ; Allocates 3 words. Middle word is initialized to 52.
DATA ENDS
```

### The `DUP` (Duplicate) Operator
Used to generate large blocks of data or arrays without typing each element.
*Syntax:* `Exp DUP (OP1, OP2, ... OPN)`
```assembly
DATA SEGMENT
    ARRAY1 DB 2 DUP(0, 1, 2, ?)         ; Allocates 8 bytes: 0, 1, 2, ?, 0, 1, 2, ?
    ARRAY2 DB 100 DUP(?)                ; Allocates an array of 100 uninitialized bytes
    ARRAY3 DB 100 DUP(0, 2 DUP(1,2), 0, 3) ; Nested DUPs are allowed!
DATA ENDS
```

### Creating Arrays of Pointers
You can allocate arrays that hold the memory addresses of other variables.
```assembly
DATA SEGMENT
    PAR1 DW 1234H
    PAR2 DW 5678H
    
    ; This table holds the 16-bit offset addresses of PAR1 and PAR2
    PARAMETER_TABLE DW PAR1
                    DW PAR2
DATA ENDS
```

---

## 6.2 Overriding Types and Ambiguity Resolution
Sometimes you must perform an operation where the size (byte vs word) is ambiguous or contradicts the original variable definition.

### The `PTR` (Pointer) Operator
Forces the assembler to treat a memory location as a specific size.
```assembly
DATA SEGMENT
    OPER1 DB ?, ?      ; Two 8-bit bytes
    OPER2 DW ?, ?      ; Two 16-bit words
DATA ENDS

CODE SEGMENT
    ASSUME CS:CODE, DS:DATA
START:
    ; ERROR: OPER1 is defined as DB (Byte), but AX is 16-bit!
    ; MOV OPER1+1, AX  

    ; CORRECT: Force assembler to treat OPER1+1 as the start of a 16-bit word
    MOV WORD PTR OPER1+1, AX

    ; CORRECT: Force assembler to treat OPER2 as just an 8-bit byte to fit into AL
    MOV BYTE PTR OPER2, AL
CODE ENDS
```

### The `LABEL` Directive
Assigns a secondary name and type to an existing memory offset, allowing you to access the same memory as either bytes or words without needing `PTR` everywhere.
```assembly
DATA SEGMENT
    BYTE_ARRAY LABEL BYTE       ; Treat the following data as bytes
    WORD_ARRAY DW 50 DUP(?)     ; Actually allocates 50 words (100 bytes)
DATA ENDS

CODE SEGMENT
    MOV WORD_ARRAY+2, 0         ; Clears a 16-bit word
    MOV BYTE_ARRAY+2, 0         ; Clears an 8-bit byte at the exact same physical location
CODE ENDS
```

---

## 6.3 Aliases and Macros (`EQU`)
* **`EQU` (Equate):** Works like `#define` in C. It acts as a find-and-replace for the assembler. It does NOT allocate any memory.

```assembly
NUM EQU 6                            ; Define a constant named NUM
INDXD_CHAR EQU CHAR_ARRAY[SI+10]     ; Define an alias for a complex memory operation

CODE SEGMENT
    ADD BX, NUM                      ; Assembler translates to: ADD BX, 6
    MOV AL, INDXD_CHAR               ; Assembler translates to: MOV AL, CHAR_ARRAY[SI+10]
CODE ENDS
```

---

## 6.4 Segment Definitions
Used to tell the assembler how to organize your logical memory blocks.

* **`SEGMENT` and `ENDS` (End Segment):** Demarcates the boundaries of a segment.
* **`ASSUME`:** Tells the assembler which physical segment register corresponds to which logical segment you defined.
* **`END`:** Marks the absolute physical end of the source code file. Everything below `END` is ignored.

```assembly
DATA SEGMENT
    VAR1 DB 55H
DATA ENDS

CODE SEGMENT
    ASSUME CS:CODE, DS:DATA      ; Link CS to CODE segment, DS to DATA segment
START:
    ; Main code goes here
CODE ENDS
END START                        ; Denotes the end of the file and the entry label
```

---

## 6.5 Alignment Directives
* **`EVEN`:** Forces the next variable to be placed at an even memory address. Essential because 16-bit word fetches from even addresses take 1 bus cycle, while odd addresses take 2 bus cycles (Unaligned Memory Access).
* **`ORG` (Origin):** Forces the assembler to set the internal location counter to a specific physical offset.

```assembly
VECTORS SEGMENT
    ORG 10H             ; Force next variable to be at physical offset 0010H
    VECT1 DW 1234H

    ORG 20H             ; Jump to offset 0020H
    VECT2 DW 5678H
VECTORS ENDS
```

---

## 6.6 Value Returning Attribute Operators
These operators ask the assembler to calculate and return metadata about a variable during compile time.

```assembly
DATA SEGMENT
    A DW 100 DUP(0)      ; An array of 100 words (200 bytes total)
DATA ENDS

CODE SEGMENT
    ; LENGTH: Returns the number of elements in an array defined by DUP.
    MOV CX, LENGTH A     ; CX = 100

    ; SIZE: Returns the total number of bytes allocated (LENGTH x TYPE).
    MOV CX, SIZE A       ; CX = 200 (100 words * 2 bytes/word)

    ; OFFSET: Returns the 16-bit offset address of the variable inside its segment.
    MOV BX, OFFSET A     ; BX = 0000H (Assuming 'A' is the very first variable in DATA segment)

    ; SEG: Returns the 16-bit Segment Base Address.
    MOV AX, SEG A        ; Equivalent to loading DS

    ; TYPE: Returns the size of a single element in bytes (DB=1, DW=2, DD=4).
    ADD SI, TYPE A       ; SI = SI + 2 (Since A is a DW)
CODE ENDS
```
