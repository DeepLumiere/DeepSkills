## 1. Overview & Foundational Definitions

### 1.1 What is a Computer Network?

• Faculty Definition: A computer network is a set of autonomous computers interconnected by a single technology to share
resources, exchange data, and facilitate communication. [Faculty — Slide 2]
• General / Reference Definition: A computer network is an interconnected collection of autonomous computers. Two
computers are
said to be interconnected if they are able to exchange information. The connection need not be via a copper wire; fiber
optics,
microwaves, infrared, and communication satellites can also be used. [General — Slide 2]
• Key Terminologies:
• Node: Any device (e.g., computer, printer, router, switch) capable of sending and/or receiving data generated by other
nodes on the network. [Faculty + General]
• Communication Link: The physical or wireless medium (e.g., coaxial cable, twisted pair, optical fiber, radio waves)
connecting nodes. [Faculty + General]
• Autonomous: A computer is autonomous if it can function independently without master-slave control by another
computer. A
system with one control computer and multiple slave terminals is not a computer network. [General — Slide 2]

### 1.3 Core Characteristics of Computer Networks

1. Fault Tolerance: The network must route traffic around failed hardware or links so that failure of a single node or
   link does
   not bring down overall communication. [Faculty — Slide 4]
2. Scalability: The ability of the network to expand efficiently (adding new nodes, networks, and services) without
   suffering
   severe performance degradation. [Faculty — Slide 4]
3. Quality of Service (QoS): The capability of a network to provide better service to selected network traffic over
   various
   technologies (managing delay, jitter, throughput, and packet loss). [Faculty — Slide 4]
4. Security: Protecting network assets and data against unauthorized access, corruption, or interception (ensuring
   Confidentiality, Integrity, and Availability - CIA). [Faculty — Slide 4]

## 3. Network Hardware Classification

### 3.1 Classification by Transmission Technology

#### A. Broadcast Links

• A single communication channel is shared by all machines on the network.
• Packets sent by any machine are received by all machines on the network.
• An address field inside the packet header specifies the intended recipient.
• Nodes inspect the destination address: if addressed to them, they process it; otherwise, they ignore
it. [Faculty — Slide 13 /
General — Slide 13]

Addressing Modes in Broadcast Networks:

1. Unicast: Packet intended for exactly one node.
2. Multicast: Packet intended for a subset of nodes (indicated by a special multicast bit/address).
3. Broadcast: Packet intended for all nodes on the network (indicated by a reserved broadcast address, e.g., all 1s in
   binary).
   [Faculty — Slide 15 / General — Slide 15]

#### B. Point-to-Point Links

• Consists of many connections between individual pairs of machines.
• To go from source to destination, a packet may have to visit one or more intermediate nodes.
• Routing algorithms are required to find optimal paths through the network.
• Generally used in larger, wide-area networks (WANs). [Faculty — Slide 14 / General — Slide 14]

### 3.3 Key Hardware & Switching Terms

• Packet: A discrete block of data containing a header (control info, addresses) and payload (actual
data). [General — Slide 23]
• Packet Switching: Transmission technique where data stream is divided into packets that are routed independently
across shared
network links. [General — Slide 23]
• Circuit Switching: A dedicated physical path (circuit) is established between sender and receiver for the entire
duration of
the call (e.g., traditional telephone network). [Faculty — Slide 43]
• Datagram: A connectionless packet transfer mechanism where each packet carries full source and destination addresses
and is
routed independently. [General — Slide 23]
• Virtual Circuit: A connection-oriented packet switching technique where a pre-planned logical path is established
through
routers before data packets are sent. [General — Slide 23]

## 4. Network Software & Layered Architecture

### 4.1 Protocol Hierarchies

To reduce design complexity, most networks are organized as a stack of layers or levels, each built upon the one below
it.

• Layer: A module designed to perform a specific abstraction or task. [Faculty + General — Slide 24]
• Protocol: An agreement/set of rules between the communicating parties (peer entities) on how communication is to take
place
across a layer. [Faculty + General — Slide 24-25]
• Interface: Defines which primitive operations and services the lower layer offers to the layer directly above
it. [Faculty +
General — Slide 25]
• Network Architecture: A set of layers and protocols. The specification of the architecture must contain enough
information to
allow an implementer to write the software or build the hardware for each layer. [Faculty + General — Slide 25]
• Protocol Stack: The specific list of protocols used by a system, one protocol per
layer. [Faculty + General — Slide 25]
──────

1. Layer N receives a Service Data Unit (SDU) from Layer N + 1.
2. Layer N prepends its own Header (

### 4.4 Major Layer Design Issues

1. Addressing: Identifying senders and receivers across layers.
2. Error Control: Detecting and correcting bit errors introduced by physical links.
3. Flow Control: Preventing a fast sender from swamping a slow receiver.
4. Multiplexing & Demultiplexing: Combining multiple upper-layer conversations onto a single lower-layer channel, and
   separating
   them at the destination.
5. Routing: Choosing optimal paths through a mesh of intermediate routers.
6. Scalability & Security: Ensuring performance holds as network grows, and preventing
   tampering/eavesdropping. [Faculty — Slide
   24 / General — Slide 24]

## 5. Connection-Oriented vs. Connectionless Services

### 5.1 Detailed Breakdown

                                 Services
                                    |
            +-----------------------+-----------------------+
            |                                               |
    Connection-Oriented                             Connectionless
    (Telephone Model)                               (Postal Mail Model)
      1. Setup Connection                             1. Packets sent independently
      2. Use Connection                               2. No setup / teardown
      3. Release Connection                           3. Packets may arrive out-of-order

1. Connection-Oriented Service:
   • Patterned after the telephone system.
   • Requires establishing a connection prior to sending data, using it for data transfer, and tearing it down
   afterwards.
   • Acts like a pipe: sender pushes bits in at one end, receiver extracts them in the exact same order at the other
   end.
   [Faculty + General — Slide 28]
2. Connectionless Service:
   • Patterned after the postal system.
   • Each message (datagram) carries the full destination address and is routed independently through the intermediate
   nodes.
   • Later-sent packets may arrive before earlier-sent packets (out-of-order delivery). [Faculty + General — Slide 28]

## 6. Service Primitives & Relationship to Protocols

### 6.1 Service vs. Protocol (Crucial Distinction)

• Service: A set of primitive operations that a lower layer provides to the layer above it. The service defines what
operations
the layer is prepared to perform, but says nothing about how these operations are implemented (Vertical Interface
abstraction).
[Faculty + General — Slide 31]
• Protocol: A set of rules governing the format and meaning of frames, packets, or messages that are exchanged between
peer
entities within the same layer across different machines (Horizontal Interaction). [Faculty + General — Slide 31]

      Host A (Layer N+1)                             Host B (Layer N+1)
          |                                              ^
          | Service Primitive                            | Service Primitive
          v (Vertical)                                   | (Vertical)
      Host A (Layer N)   <===== Layer N Protocol =====>  Host B (Layer N)
                                  (Horizontal)
    ──────

|------------|---------|----------------------------------------------------|
| LISTEN     | Passive | Block waiting for an incoming connection request   |
| CONNECT    | Active  | Establish a connection by sending a request packet |
| ACCEPT     | Active  | Accept an incoming connection request              |
| RECEIVE    | Passive | Block waiting for an incoming data packet          |
| SEND       | Active  | Send a data packet to the peer entity              |

## 7. Reference Models

### 7.1 The OSI Reference Model (7 Layers)

Developed by the International Organization for Standardization (ISO). [Faculty + General — Slide 32-35]

#### ISO OSI Principles for Layering:

1. A layer should be created where a different abstraction is needed.
2. Each layer should perform a well-defined function.
3. The function of each layer should be chosen with an eye toward defining internationally standardized protocols.
4. Layer boundaries should be chosen to minimize information flow across interfaces. [General — Slide 33]

```text
+-----------------------------------+
| 7. Application Layer              |
+-----------------------------------+
| 6. Presentation Layer             |
+-----------------------------------+
| 5. Session Layer                  |
+-----------------------------------+
| 4. Transport Layer                |  <-- End-to-End Control
+-----------------------------------+
| 3. Network Layer                  |  <-- Subnet Routing
+-----------------------------------+
| 2. Data Link Layer                |  <-- Node-to-Node Hop
+-----------------------------------+
| 1. Physical Layer                 |  <-- Bit Stream Transmission
+-----------------------------------+
```
#### Functions of the 7 OSI Layers:

1. Physical Layer (Layer 1): Transmits raw bits over a communication channel. Defines voltage levels, bit timing, pin
   counts,
   and transmission media specs. [Faculty — Slide 35]
2. Data Link Layer (Layer 2): Takes raw transmission facility and transforms it into a line that appears free of
   undetected
   transmission errors. Groups bits into frames, handles frame synchronization, error detection/correction, and flow
   control.
   [Faculty — Slide 35]
3. Network Layer (Layer 3): Controls the operation of the subnet. Handles packet routing, congestion control, and
   internetworking between heterogeneous networks. [Faculty — Slide 35]
4. Transport Layer (Layer 4): Accepts data from Session layer, splits it up into smaller units, passes these to Network
   layer,
   and ensures that all pieces arrive correctly at the other end. True end-to-end layer. [Faculty — Slide 35]
5. Session Layer (Layer 5): Allows users on different machines to establish sessions between them. Provides dialog
   control
   (keeping track of whose turn it is to transmit) and synchronization (inserting checkpoints into long
   transfers). [Faculty —
   Slide 35 / General — Slide 57]
6. Presentation Layer (Layer 6): Concerned with the syntax and semantics of the information transmitted. Handles data
   format
   conversions, encoding, data compression, and encryption. [Faculty — Slide 35 / General — Slide 57]
7. Application Layer (Layer 7): Contains a variety of protocols that users commonly need (HTTP, FTP, SMTP,
   DNS). [Faculty —
   Slide 35]
   ──────

### 7.2 The TCP/IP Reference Model (4 Layers)

Developed by the US Department of Defense (DoD) for ARPANET. [Faculty + General — Slide 36-38]

      TCP/IP Layers                       Key Protocols
      +-------------------+              +-------------------------------+
      | Application Layer |              | HTTP, FTP, SMTP, DNS, SSH     |
      +-------------------+              +-------------------------------+
      | Transport Layer   |              | TCP, UDP                      |
      +-------------------+              +-------------------------------+
      | Internet Layer    |              | IP, ICMP, ARP, RARP           |
      +-------------------+              +-------------------------------+
      | Link / Host-to-   |              | Ethernet, 802.11 Wi-Fi, PPP   |
      | Network Layer     |              |                               |
      +-------------------+              +-------------------------------+

#### Functions of the TCP/IP Layers:

1. Link Layer (Host-to-Network): Describes what links (such as serial lines or Ethernet) must do to meet the needs of
   the
   connectionless Internet layer. It is not really a layer in the strict sense, but an interface between hosts and
   transmission
   links. [General — Slide 36]
2. Internet Layer: The linchpin of the architecture. Defines an official packet format and protocol called IP (Internet
   Protocol). Routes IP packets to their destinations independently. Handles packet delivery across network
   boundaries. [General —
   Slide 36]
3. Transport Layer: Allows peer entities on the source and destination hosts to carry on a conversation.
   • TCP (Transmission Control Protocol): Reliable connection-oriented, byte-stream protocol. Provides flow control and
   congestion control.
   • UDP (User Datagram Protocol): Unreliable connectionless datagram protocol for applications that prefer low latency
   over
   reliability. [General — Slide 36]
4. Application Layer: Contains all higher-level protocols (HTTP, Telnet, FTP, SMTP, DNS). [General — Slide 36]
   ──────

### 7.5 Critiques of the Models

#### A. Critique of the OSI Model ("The Four Bads") [Faculty + General — Slide 41]

1. Bad Timing: The OSI standards were published after TCP/IP was already heavily deployed in universities and industry (
   The
   "Elephant Problem": TCP/IP took over the market before OSI was finalized).
2. Bad Technology: Session and Presentation layers are virtually empty; Data Link and Physical layers are heavily
   redundant;
   complex and inefficient implementation.
3. Bad Implementation: Initial OSI implementations were slow, bulky, and buggy compared to TCP/IP.
4. Bad Politics: OSI was seen as government/telecom bureaucrat-driven, while TCP/IP was seen as open-source academic
   hacker-
   driven.

#### B. Critique of the TCP/IP Model

1. Does not clearly distinguish between concepts of service, interface, and protocol.
2. Not general; hard to adapt to describe protocol stacks other than TCP/IP.
3. The Link layer is not really a layer in the architectural sense, but an interface.
4. Completely omits physical and data link layer specifications. [General — Slide 41]

## 1. Overview & Design Issues

### 1.1 Role and Core Objectives of Data Link Layer

• The Physical Layer delivers raw bits over a physical medium. However, physical channels suffer from:
• Limited bandwidth
• Signal distortions and bit errors
• Propagation delays [Faculty — Slide 3]
• Primary Objective of Data Link Layer: To transform a raw transmission facility into a line that appears free of
undetected
transmission errors to the Network Layer above it. [Faculty — Slide 4]
──────

### 1.2 Functions of Data Link Layer

1. Providing a well-defined service interface to the Network Layer.
2. Framing: Grouping physical bit streams into discrete units called frames.
3. Error Handling: Detecting and correcting errors (corrupted, lost, or duplicate frames).
4. Flow Control: Regulating data transmission rate so fast senders do not overwhelm slow receivers. [Faculty — Slide 4]
   ──────

### 1.3 Layer Relationship & Implementation Architecture

• Virtual vs. Actual Communication: The Data Link Layer entities communicate virtually via a Data Link Protocol, but
actual data
flows down to the Physical Layer, across the physical medium, and back up. [Faculty — Slide 6 / General — Slide 9]

      Host A (Network Layer)                           Host B (Network Layer)
                |                                                ^
                v Virtual Data Link Protocol Path                |
      Host A (Data Link Layer) =====================> Host B (Data Link Layer)
                |                                                ^
                v Actual Physical Transmission Path              |
      Host A (Physical Layer)  ---------------------> Host B (Physical Layer)

• Hardware vs. Software Implementation:
• NIC (Network Interface Card): Handles Physical Layer processes and time-critical Data Link Layer functions (framing,
CRC
hardware check, bit stuffing).
• OS Kernel Device Driver: Handles higher link-layer logic, software timers, and Network Layer interactions on the main
CPU.
[Faculty — Slide 34 / General — Slide 32]

──────

### 1.4 Services Offered to Network Layer

1. Unacknowledged Connectionless Service:
   • Source sends independent frames without destination acknowledging them.
   • No connection setup or release.
   • Lost frames are not recovered by the link layer.
   • Use Cases: Low error rate channels (copper LANs) or real-time voice traffic where delay is worse than lost frames.
   [Faculty — Slide 8 / General — Slide 11]
2. Acknowledged Connectionless Service:
   • Source sends independent frames, but each frame is individually acknowledged by the receiver.
   • If a frame does not arrive within a timeout period, it is retransmitted.
   • Use Cases: Highly unreliable wireless links (e.g., IEEE 802.11 Wi-Fi). [Faculty — Slide 9 / General — Slide 12]
3. Acknowledged Connection-Oriented Service:
   • Connection is established before any data is sent.
   • Frames are numbered, acknowledged, and guaranteed to arrive exactly once and in the correct order.
   • Three Phases: Connection Establishment → Data Transfer → Connection Release.
   • Use Cases: Long-distance point-to-point satellite channels. [Faculty — Slide 10 / General — Slide 13]

## 2. Framing

### 2.1 Why Framing is Necessary

Physical Layer delivers a continuous stream of raw bits. To detect and recover from errors, the stream must be broken
down into
discrete Frames, so checksums can be computed for each frame. [Faculty — Slide 11 / General — Slide 14]
──────

### 2.2 Framing Methods

#### Method 1: Character Count / Byte Count

• Uses a field in the frame header to specify the total number of characters/bytes in the frame.
• Mechanism: Receiver reads the count field to know where the frame ends. [Faculty — Slide 12 / General — Slide 15]

      Frame 1 (5 bytes)     Frame 2 (5 bytes)     Frame 3 (8 bytes)
      +---+---+---+---+---+ +---+---+---+---+---+ +---+---+---+---+---+---+---+---+
      | 5 | 1 | 2 | 3 | 4 | | 5 | 5 | 6 | 7 | 8 | | 8 | 9 | 0 | 1 | 2 | 3 | 4 | 5 |
      +---+---+---+---+---+ +---+---+---+---+---+ +---+---+---+---+---+---+---+---+

• Fatal Flaw / Disadvantage: If a single bit error corrupts the count field (e.g., a 5 becomes a 7), the receiver loses
frame
synchronization completely and cannot locate the start of subsequent frames. [Faculty — Slide 12 / General — Slide 16]
──────

#### Method 2: Flag Bytes with Byte Stuffing (Character Stuffing)

• Delimits frames with special control bytes called FLAG bytes (e.g., ASCII DLE STX / DLE ETX or 0x7E).
• Problem: What if the binary payload data itself contains the byte value matching FLAG?
• Byte Stuffing Rule:
• Sender inserts a special Escape byte (ESC) (e.g., 0x7D) immediately before any instance of FLAG or ESC occurring
within
the payload.
• Receiver strips off the ESC byte upon reception. [Faculty — Slide 13-16 / General — Slide 17-19]

      Original Payload:       [ A ] [ FLAG ] [ B ]
      Transmitted (Stuffed):  [ FLAG ] [ A ] [ ESC ] [ FLAG ] [ B ] [ FLAG ]

      Original Payload:       [ A ] [ ESC ] [ B ]
      Transmitted (Stuffed):  [ FLAG ] [ A ] [ ESC ] [ ESC ] [ B ] [ FLAG ]
    ──────

#### Method 3: Flag Bits with Bit Stuffing

• Allows frames to contain an arbitrary number of bits (bit-oriented framing).
• Frame start and end are marked by the special flag bit pattern: 01111110 (six consecutive 1s).
• Bit Stuffing Rule (Sender):
• Whenever sender's data link layer encounters FIVE consecutive 1s in the payload, it automatically stuffs a 0 bit
immediately after them into the outgoing bit stream.
• Destuffing Rule (Receiver):
• When receiver sees five consecutive 1s followed by a 0 bit, it automatically strips out the 0 bit.
• If followed by a 1 bit and a 0 bit, it is a valid end-of-frame FLAG (01111110).
• If followed by two 1 bits, an error has occurred (01111111). [Faculty — Slide 17-20 / General — Slide 20-22]

      Original Data:      01101111111001111101
      Stuffed Stream:     0110111110110011111001
                                  ^         ^
                            (Stuffed 0s inserted)
    ──────

#### Method 4: Physical Layer Coding Violations

• Used in networks where Physical Layer encoding has inherent redundancy (e.g., Manchester encoding where every bit
period has a
signal transition).
• High-High or Low-Low signals are invalid data transitions; they are used as delimiters to mark frame
boundaries. [Faculty —
Slide 21 / General — Slide 24]

## 3. Error Detection and Correction

### 3.1 Error Types

• Single-Bit Error: Only 1 bit of a data unit is inverted.
• Burst Error: 2 or more bits in a data unit are corrupted. Length of burst k is measured from the first corrupted bit
to the
last corrupted bit. [Faculty — Slide 22]
──────

### 3.2 Error Control Strategies

• Forward Error Correction (FEC): Sender includes enough redundant bits for receiver to detect AND correct errors
without
retransmission. Used on noisy/high-delay channels (wireless, satellite). [Faculty — Slide 22 / General — Slide 25]
• Automatic Repeat reQuest (ARQ): Sender includes just enough redundancy to detect errors. Receiver requests
retransmission upon
detecting error. Used on low-noise channels (optical fiber). [Faculty — Slide 22 / General — Slide 25]
──────

### 3.3 Hamming Distance & Code Distance Principles

#### Definition: Hamming Distance

The number of bit positions in which two binary codewords differ. Calculated by performing an XOR operation between two
codewords and counting the number of 1s in the result. [Faculty — Slide 24 / General — Slide 26]

#### Formulas & Mathematical Rules:

### Formula: Error Detection Requirement

$$
d_{\text{min}} \ge d + 1
$$

To detect **d** single-bit errors, the minimum Hamming distance \(d_{\text{min}}\) of the code must be at least **d + 1**.
[Faculty — Slide 25]

---

### Formula: Error Correction Requirement

$$
d_{\text{min}} \ge 2p + 1
$$

To correct **p** single-bit errors, the minimum Hamming distance \(d_{\text{min}}\) must be at least **2p + 1**.
[Faculty — Slide 25]

---

### 3.4 The Hamming Code (Single-Bit Error Correcting Code)

#### Rules of Hamming Code Construction:

1. Bit positions are numbered starting at 1 (1, 2, 3, 4, 5, 6, 7...).
2. Check bits (Parity bits \(P_k\)) are placed at positions that are powers of 2: 1, 2, 4, 8, 16…(\(2^k\)).
3. Data bits (\(D_j\)) fill all remaining positions (3, 5, 6, 7, 9…).
[Faculty — Slide 27 / General — Slide 27]

---

### Formula: Relationship Between Data Bits and Redundant Check Bits

For **m** data bits and **r** redundant check bits:

$$
(m + r + 1) \le 2^r
$$

[Faculty — Slide 27]

### Parity Computation Groups:

- \(P_1\) checks positions (1,3,5,7):

- \(P_2\) checks positions (2,3,6,7):

P_2 = 1
$$

- \(P_4\) checks positions (4,5,6,7):

### 4.1 Definition

Mechanisms to prevent a fast transmitting node from swamping a slower receiving node with more data than its buffers can

### 4.2 Three Flow Control Strategies

                             Flow Control Strategies
                                       |
             +-------------------------+-------------------------+
             |                         |                         |
       Feedback-Based             Rate-Based               Credit-Based
     (Receiver sends ACKs)    (Built-in Rate Limit)   (Receiver grants credits)

1. Feedback-Based Flow Control: Receiver sends feedback messages back to the sender giving explicit permission to
   transmit more
   data (e.g., Stop-and-Wait, Sliding Window ACKs). [Faculty — Slide 28 / General — Slide 28]

   frames. [Faculty — Slide 29 / General — Slide 29]

### 6.5 Protocol 5: Go-Back-N (GBN)

#### Key Characteristics:

• Sender Window Wₛ > 1, Receiver Window Wᵣ = 1.
• Receiver discards all out-of-order frames and sends cumulative ACKs for the last correctly received in-order frame.
• On timeout, sender retransmits ALL unacknowledged outstanding frames starting from the oldest unacked
frame. [Faculty — Slide
51 / General — Slide 56]

#### Crucial Rule: Maximum Window Size for Go-Back-N

### Formula: Maximum Sender Window Size (GBN)

[
W_s \le \text{MAX_SEQ} = 2^n - 1
]

• Reason / Proof: If sequence numbers are 3 bits (0 to 7, size 8), and Wₛ = 8:
• Sender transmits frames 0..7. Receiver receives all 8 frames and expects frame 0 next.
• All ACKs are lost in transit.
• Sender timeout occurs and retransmits frame 0.
• Receiver cannot distinguish whether frame 0 is a retransmission or a brand new frame 0 from the next sequence cycle!
• Setting Wₛ = 7 (2ⁿ - 1) prevents this ambiguity. [Faculty — Slide 52 / General — Slide 58]

──────

### 6.6 Protocol 6: Selective Repeat (SR)

#### Key Characteristics:

• Sender Window Wₛ > 1, Receiver Window Wᵣ > 1.
• Receiver accepts and buffers out-of-order frames within its window.
• Receiver sends a NAK (Negative Acknowledgement) to trigger fast retransmission of only the missing frame.
• Sender retransmits ONLY the single corrupted/missing frame upon receiving a NAK or timer
expiry. [Faculty — Slide 57 / General
— Slide 68]

#### Crucial Rule: Maximum Window Size for Selective Repeat

### Formula: Maximum Window Size (Selective Repeat)

[
W_s = W_r \le \frac{\text{MAX_SEQ} + 1}{2} = 2^{n-1}
]

• Reason / Proof: If sequence space is 0..7 (8 numbers), max window size is 4.
• If Wₛ = 5, sender sends 0,1,2,3,4. Receiver receives and ACKs them, advancing its window to 5,6,7,0,1.
• If all ACKs are lost, sender retransmits frame 0.
• Receiver's new window contains 0; it would mistakenly accept the old duplicate frame 0 as new data!
• Restricting Wₛ ≤ 2ⁿ⁻¹ guarantees no overlap between old and new sequence
windows. [Faculty — Slide 58 / General — Slide
77]

### 7.3 ADSL (Asymmetric Digital Subscriber Loop)

- Provides broadband Internet over legacy copper telephone local loops.
- Protocol Stack:

$$
\text{IP} \rightarrow \text{PPP} \rightarrow \text{AAL5} \rightarrow \text{ATM} \rightarrow \text{ADSL Physical}
$$

- AAL5 Frame: Encapsulates PPP data, pads payload to multiples of 48 bytes, and appends an 8-byte trailer containing length and CRC-32.

d_{\text{min}} \ge d+1
$$

### 2. Error Correction Requirement

$$
d_{\text{min}} \ge 2p+1
$$

### 3. Hamming Code Check Bit Condition

$$
(m+r+1) \le 2^r
$$

---

### 4. Frame Transmission Time

$$
T_{\text{frame}}=\frac{L}{B}
$$

Where:

- \(L\) = Frame length (bits)
- \(B\) = Bandwidth (bits/sec)

---

### 5. Stop-and-Wait Efficiency

$$
\eta=\frac{T_{\text{frame}}}{T_{\text{frame}}+RTT}
$$

or

$$
\eta=\frac{1}{1+2a}
$$

---

### 6. Bandwidth-Delay Product

$$
BDP=B \times RTT
$$

---

### 7. Maximum Sender Window Size (Go-Back-N)

$$
W_s \le 2^n-1
$$

---

### 8. Maximum Sender Window Size (Selective Repeat)

$$
W_s \le 2^{n-1}
$$

### 8.2 Important Definitions

• Framing: Grouping bits from the Physical Layer into discrete frames with headers/trailers.
• Bit Stuffing: Inserting a 0 bit after five consecutive 1s to prevent payload data from matching the 01111110 flag.
• Hamming Distance: Number of bit positions in which two binary codewords differ.
• Piggybacking: Delaying ACKs to attach them to outgoing data frame headers.
• Pipelining: Transmitting multiple frames before receiving an acknowledgment for the first frame.
──────

### 8.3 Important Comparisons

• Forward Error Correction (FEC) vs ARQ: Self-correcting via redundancy (high overhead, noisy links) vs detecting &
retransmitting (low overhead, clean links).
• Byte Stuffing vs Bit Stuffing: ESC byte insertion before FLAG/ESC bytes vs single 0 bit insertion after five 1s.
• Go-Back-N vs Selective Repeat: Receiver window 1 / discards out-of-order / retransmits whole window vs Receiver
window > 1 /
buffers out-of-order / retransmits only missing frame via NAK.
